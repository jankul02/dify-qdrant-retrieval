# VS Code Copilot — Agent Entry Point

**Read this file first. It is loaded automatically by Copilot in VS Code.**

## Quick Start

1. Type `!start [goal]` to begin a session
2. Work freely — ABW (Always Be Working) mode, no confirmations
3. Type `!end` to close, commit, merge, and push

## Session Protocol

### !start [goal]

When you receive `!start [goal]`:

1. **Read context files** (in order):
   - `agentic/rules_common.md`
   - `agentic/rules_project.md`
   - `PROJECT_MAP.md`
   - `docs/dev/sessions/current.md`
   - `README.md`
2. **Check git state**:
   - Run `git status` and `git log --oneline -5`
   - Report as traffic light:
     - 🟢 **Clean** — git clean, session closed → proceed
     - 🟡 **Attention** — uncommitted changes, session closed → ask: incorporate or set aside?
     - 🔴 **Incomplete** — uncommitted changes AND session still open → ask: resume or fresh start?
3. **Ask for goal** if not provided after `!start`
4. **Ask for branch**:
   - **[N]ew** `session/YYYY-MM-DD-slug` from current branch
   - **[S]tay** on current branch
   - **[M]ain/master** (default branch)
5. **If new branch**: run `sh scripts/session_start.sh <YYYY-MM-DD-slug>`
6. **Write** goal + start time to `docs/dev/sessions/current.md`
7. **Enter ABW mode**

### In-Session Freedom (ABW — Always Be Working)

Once `!start` is complete and the session is open:

- **No confirmations needed** for file edits, terminal commands, or script execution within the repo
- **Full repo access**: read, edit, create, delete files and folders freely
- **Use native VS Code tools** (Read/Edit) for file changes — not shell commands
- **Every logic change** must be immediately reflected in relevant docs (doc-sync)

#### Hard Safety Exceptions (always ask, never auto)

- `git push --force` / `git push --force-with-lease`
- Dropping Qdrant collections (`DELETE /collections/...`)
- `rm -rf` on paths **outside** the repo root
- Committing secrets (`.env`, tokens, credentials, keys)

### !end

When you receive `!end`:

1. **Summarize changes** (one line)
2. **Update session docs**:
   - `docs/dev/sessions/current.md` — set status to Closed, write outcome
   - `docs/dev/sessions/history.md` — append session entry
   - `PROJECT_MAP.md` — update if files were added/renamed
   - `docs/dev/open_points.md` — update if new issues emerged
   - `docs/dev/plans.md` — update if plans changed
3. **Stage changes**: run `sh scripts/session_end.sh`
4. **Commit and merge**:
   ```bash
   git commit -m 'session: <agent-composed summary>'
   make session-merge
   git push
   ```
   `make session-merge` squash-merges to main with the same message — one commit on main, no duplicate.

## Offline Mode

This protocol works **fully offline**:
- No cloud API calls required for session management
- Git operations are local until `git push`
- All session state is stored in `docs/dev/sessions/`
- Use `git push` only when online and explicitly requested

## Response Style

- Concise — no padding, no trailing summaries
- One sentence per status update
- Match response length to task complexity

## Code Conventions

- Edit existing files; create new ones only when needed
- No comments unless the WHY is non-obvious
- No features beyond what is asked
- Use native VS Code Read/Edit tools for file changes
- Keep files short — split when >150 lines

## Navigation (large codebases)

- Check `PROJECT_MAP.md` before opening files
- Read only the lines you need, not whole files
- Use grep/search to locate symbols before reading source
